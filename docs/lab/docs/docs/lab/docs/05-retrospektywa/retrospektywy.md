# Retrospektywy

Retrospektywy zespołu projektu „Platforma do prowadzenia lig i turniejów e-sportowych”. Liczby pochodzą z [estymacji](../02-planowanie/estymacja.md), metryki zbiorczo w [metryki.md](metryki.md).

## Sprint 1

| Metryka | Wartość |
|---------|---------|
| Zaplanowano | 43 SP |
| Zrobiono | 23 SP |
| Realizacja planu | około 53% |

### Co poszło dobrze

- Frontend szedł prawie zgodnie z planem.
- Zespół rozpisał historyjki z kryteriami akceptacji, a backlog dostał priorytety MoSCoW.

### Co nie poszło

- Backend dopiero się rozkręcał, przez co zabrakło zrobionych zadań po stronie API.
- Wiele historyjek nie było rozpisanych, bo nie było ich na ekranach z Figmy: dopiero przy rozpisywaniu doszło 47 SP (drużyny, zaproszenia, tworzenie rozgrywek, zapisy, ekran logowania, panel admina).
- Przy tempie z Sprintu 1 (23 SP) plan na pozostałe sprinty (około 52 SP na sprint) jest nierealny.

### Wnioski i działania

| Działanie | Opis |
|-----------|------|
| Kolejność pracy | Najpierw Must, potem Should, na końcu Could. |
| Wyrównanie obciążenia | W Sprincie 3 na backendzie jedna osoba ma 18 SP, a druga 10 SP: część zadań zostaje przerzucona. |
| Przegląd nowych zadań | Zadania z gwiazdką przechodzimy razem na planowaniu Sprintu 3. |
| Co odpuszczamy najpierw | Log aktywności, logowanie przez Discord, panel admina; wyniki na żywo ewentualnie zastąpione odświeżaniem strony. |
| Poprawianie liczb | Po każdym sprincie aktualizujemy estymację. |
